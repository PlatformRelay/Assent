**1. CRITICAL | cmd/assent/run.go:139 + internal/forge/github (endpoint wiring) + action.yml:79-85 + README.md quick-start | `--forge github` sends GITHUB_TOKEN to gitlab.com.** The `-gitlab-endpoint` flag defaults to `https://gitlab.com` (run.go:139); `selectForge` only substitutes `https://api.github.com` when the endpoint is *empty* (forge_select.go:40-45), and a flag default is never empty — so `selectForge("github", "https://gitlab.com")` returns the GitLab host for the GitHub adapter. `action.yml` (the S16 deliverable) and the README GitHub quick-start line both run `assent run --forge github` **without** an endpoint, so the shipped entrypoint points every REST/GraphQL call at `https://gitlab.com` with the GitHub token in the Authorization header — token dispatched to the wrong service and a run that cannot succeed. This directly contradicts the branch's own contract at forge_select.go:26-27 ("`--forge github` without an endpoint targets https://api.github.com and never GitLab's API") and cli.md's "the default follows the forge: `https://api.github.com` for `--forge github`". `doctor_forge.go:62` has the same hole (`normalizeGitLabEndpoint("")` → `https://gitlab.com`). Fix: in `selectForge`, for `KindGitHub` ignore the GitLab-named default (select on kind first, or only accept a non-default/explicit endpoint), add a test that the resolved endpoint's host is forge-consistent, and pass `--gitlab-endpoint`-equivalent (or rename the flag) in `action.yml`.
